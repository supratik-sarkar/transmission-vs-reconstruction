# Contributing

This is a research repository with a pre-registered experimental boundary. Two
rules matter more than the rest.

**No result may be entered by hand into an exported artifact.** Every table and
figure is generated by code from structured result artifacts, and every artifact
is bound to its provenance.

**No comparator may be added or removed on the basis of how it performs.** The
comparator suite and the comparative criterion are fixed before results are seen.

## Before opening a pull request

1. Never commit a credential, a source document, or an unpublished run output.
2. Do not change behaviour that a binding freeze record covers. If it must
   change, that is a documented deviation and a new pre-registration version, not
   an edit.
3. Add or update tests for every protocol-affecting change. Tests use synthetic
   fixtures only.
4. Run `make check` — lint, type check, tests and the privacy scan.

## Protocol-affecting changes

State explicitly whether the change touches any of:

- the source frame or the atom inventory
- focal sampling or inclusion probabilities
- prompts, slot schemas or the downstream task
- matcher or editor behaviour
- causal estimands or weighting
- gate computation or thresholds
- exclusion criteria
- provider configuration or decoding
- the comparator registry or the comparative rule

A change to any of these needs a rationale in the pull request body, not only in
the diff.

## Style

Follow the existing conventions: `ruff` for lint and format, type annotations
throughout, and comments that explain **why** rather than restating the code.
Where a design decision has a non-obvious alternative, say what the alternative
was and why it was rejected — several modules here exist in their current form
because a plausible simpler version was wrong.
